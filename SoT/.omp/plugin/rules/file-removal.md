Plain `rm`, `unlink`, or `shred` of a file is fine. This rule shows for a removal that can take a whole folder or the home folder, and for deletion in code.

- Do not remove recursively or in directory mode: no `rm -r`, `rm -R`, `rm -d`, a flag cluster with `r`, `R`, or `d`, `--recursive`, `--dir`, `--no-preserve-root`, or an abbreviation of one of these long options, such as `--recur` or `--di`.
- Do not remove the home folder, the root, the working folder, its parent, or every file of one of them: no `~`, `$HOME`, `${HOME}`, `/`, `.`, or `..` as an argument, also with `/` or `/*` after it, and no bare `*`.
- Do not remove or overwrite a device: no path under `/dev/` as an argument, except `/dev/null`.
- Do not delete files through `eval` code (`os.remove`, `shutil.rmtree`, `Path.unlink`, `fs.rm`, `rmSync`, `Bun.file(...).delete()`). In eval, run a shell command through `sh(...)` instead; the same limits apply there.
- To remove a temporary directory, use the `scratch_remove` tool or run `docks-kit scratch remove <path>`. Both remove only a path in the scratch root, the system temporary directory, or `/var/tmp`.
- To remove another folder, run `gio trash -- <path>` on Linux or `trash <path>` on macOS. `gio trash` fails on a `tmpfs` `/tmp`.
- To remove a path from the git index, run `git rm -- <path>`. omp denies `git rm -r`. To remove a folder from git, run `git rm -- '<dir>/*'`. To stop tracking a folder and keep its files, run `git rm --cached -- '<dir>/*'`. Keep the quotes: git then matches every file in every subfolder.
- Do not use `find -delete` or `find -exec rm`. Put the paths in your report instead.
- To remove a worktree or an ovnfs checkout that you opened, follow its row in the `workspace-hygiene` skill.
